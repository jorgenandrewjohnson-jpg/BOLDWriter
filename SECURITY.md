# Security policy

BOLD Writer is under active development. No version is currently designated as a long-term supported security release. The project handles author documents and optional AI credentials, so data loss, unsafe document parsing, unintended network transfer, or credential exposure should be treated as security issues.

Do not disclose an exploit, private document, or credential in a public issue. After the GitHub repository has **Private vulnerability reporting** enabled, use its **Security → Advisories → Report a vulnerability** form. If that form is not available yet, open a brief issue requesting a private contact method without including exploit details. Maintainers will arrange a private channel.

Include affected revision, macOS version, a synthetic reproducer, expected and actual behavior, and the likely impact. Please avoid testing against another person's documents or account. Do not send a real manuscript or API key unless a maintainer explicitly arranges a secure transfer and it is necessary.

Maintainers should acknowledge a report, assess severity, prepare a fix on a restricted branch, and coordinate disclosure after affected users can update. No fixed response-time or bounty program is promised yet.
